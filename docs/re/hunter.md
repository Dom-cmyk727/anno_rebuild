## Facts
- **D** `JAGDHAUS` (PRODTYPE 5, type 805) has its own runtime class; its tick is `0x10069f40` (gate `(u16)(t - [esi+0xa]) >= 0x1f4` = 500, `0x10069f5d`; `last += 500` at `0x10069f68`). `types.cpp` maps it to `TickKind::None`; the building is inert in the sim.
- **P** Type 805: 3x3, radius 8, input `FLEISCHTIER` (goods 137), outputs `NAHRUNG` (26) and `TIERHAEUTE` (18), per step in 57 -> out 43 / 26 (8.8), capacity 1024/1024, time 768/1280 /128, max figures 1, figure type 108 (ROUTETYPE index 12, layer 2, capacity 256). The fur trapper 824 (`PELZJAEGER`, `PELZTIER` -> `PELZE`) sends the **same figure type 108 / route 12**; the engine's `FurTrapper` tick is ported but never sends (no target: `driver.cpp`, O-25).
- **D** (shape only) `0x10069f40` after the gate: returns when both line bytes `[+0x28]`/`[+0x29]` are 0; decays the activity words `[+0x20]`/`[+0x22]` by `x*127>>7`; returns when flag bits 4/5 of `[+0xc]` are set; computes a rate `bl` from the raw store `[+0x24]` (u16) and the type property pair `0x44f`; produces into `[+0x18]`/`[+0x1a]` with the line shares `[+0x2a]` and `128 - [+0x2a]`; updates the blocked flag bit 3; at the end, when `[+0x2c]` (workers out) is 0 and a raw-stock test passes (`0x180 / type slot +0xe0` against `[+0x24] / slot +0xe4`), asks `0x10071da0(8)` for a target and creates a figure with job `0xd` through the building's slot `+0x118`. **Not decoded:** the exact production arithmetic, which unit the raw store counts, the figure creation arguments.
- **D** `0x10071da0(8)` is the radius search "nearest animal of the input goods" (`docs/re/production.md` section 4.2a); body **U**.
- **P** The scenario islands carry a `HIRSCH` record (the string at `0x100dcf24` in AnnoWelt; island templates `.scp` have none): 668 records in the 50 `.sze`, 111,352 bytes = 13,919 entries of 8 bytes; per island 15 .. 1,570 entries, many scenario islands 0 (`cache/map-needs2/N0/n0_scenes.txt`).
- **D** The reader around `0x100946c0` (loads `HIRSCH`, count = size >> 3) creates one 16-byte object per entry (vtable `0x100cac04`, init `0x1007bd50`), puts it in the island's 8x8 cell grid (`[ebp+0x94]`, row stride `[ebp+0x8c]`), fills `[obj+8]` (cell column/row bits), `[obj+9]` (a type byte: from the entry or a draw of the world generator `[ebp+0x20]` slot `+0xb4` masked `& 0x1f` plus a base) and `[obj+0xe]`. These are **map objects of the island, not figures**.
- **Documented** (`docs/sim/state.md` section 12, O-12, O-25): wildlife objects and their "fauna sweep" (`WildlifeSweep`) are unported; the sim creates no animals.
- **P** Figure types 501-505 and 514-517 have ROUTETYPE index 62 (layer 4), 506-509 route 46 (layer 2): candidates for animal figures; their relation to `HIRSCH` objects is **U**.

## N1 hunting reads (2026-11-05, second pass)
Answers to the questions above, with evidence:
1. **The quarry is a figure type, named by data (P, D).** `FigurenHeader.dat` carries, for the wild animals, `ROUTETYPE "HIRSCH"` (route index 62 in the engine's name table) and a `WARE` record naming the goods the animal yields: `FLEISCHTIER` for the entries 117-120, 122-125, 127, 132, 137, 141, 501, 504, 505 (15 entries, the 15 string occurrences in the file), `PELZTIER` for 126, 129, 514, 516, 517 (and `RAUBTIER` entries 131, 529, 530 with other goods), no `WARE` for the harmless ones (121, 128, 130, 135, 502, 503, 515, 527, 528, 531, 1206). The loader `AnnoGame 0x1000fe00` resolves that name against the 0x8f goods names (`0x100103d2`-`0x10010434`) and stores the goods index at figure type `+0x100` (`0x1001044a`); type slot `+0x80` = `0x1000fc90` returns it.
2. **The target search `0x10071da0(8)` (D).** It builds a circle from the building (centre from footprint and rotation, radius from type `+0x78`), asks the island's figure manager (city `+0x10` -> `+0x18` -> `+0x18` -> `+0xa0`, slot `+0x14`) for up to 512 figures inside it (pairs of pointer and float distance, `0x200` buffer), keeps the **nearest** (strict float `<`, start 1e18) whose figure type's goods byte (`obj +0x78() -> +0x80()`) equals the building's **input goods 0**, and returns it (null when none). No ownership, kind or state test is visible there. Float distances: the same x87 float arithmetic caveat as the other searches (OQ-162).
3. **Hunter job `0xd` (D, structure).** The job switch `0x1003b0e0` sends job `0xd` to case `0x1003b1cc`: object size `0x78`, constructor `0x1005c610`, main vtable `0x100c6f90` (run `0x1005b6c0`, arrival `0x1005c570`, abort `0x1005b740`, as the harvest job) with four step objects and the shared walk-home step: step vtables `0x100c7060` (start `0x10057690`), `0x100c7038` (start `0x10054c90`, arrival `0x10054ce0`), `0x100c7010` (start `0x10056b10`), `0x100c6fe8` (start `0x10054760`, arrival `0x100547e0`) and `0x100c4640` (walk home, `0x10057ae0`). **Not yet decoded:** what each step does (walk to the animal, the kill, the carry, the credit to the hunter's two output stores, the animal's removal).
4. **Both senders share job 0xd (D).** The fur trapper tick `0x1006e5d0` and the hunter tick `0x10069f40` both call the building's slot `+0x118` with job `0xd`; the job factory is `0x1003b0e0` (byte table `0x1003b480`, index = job - 0xd, case `0x1003b1cc`), so the body is shared. **The hunter's tick (D, shape)** ends by sending job `0xd` only with a target from (2); the figure type sent is the building's figure type 0 (108, route 12).
5. **Animals exist from load (P).** The island `HIRSCH` record (8-byte entries) is read by the island loader around `0x100946c0`; it is the only place found that makes animals at scenario load. The 16-byte object it builds is **not** yet connected to a figure of the types in 1. Whether the animals then wander (their route `HIRSCH` = job 62 = `0x3e`; the job switch has no case for `0x3e`, so the figure body is something else), respawn or only exist is **U**.
