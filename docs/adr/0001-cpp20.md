# ADR 0001: Switch to C++20

- **Status:** accepted (owner decision 2026-10-17, language gate at the end of M1); supersedes [ADR 0000](0000-implementation-language.md)
- **Date:** 2026-10-17

## Decision
The rebuild continues in **C++20**. The Rust code in `crates/` becomes the **reference implementation during the port**: it stays buildable and tested, the preview viewer keeps coming from it until the C++ viewer reaches parity, and it is deleted once every part has a C++ counterpart that passes the same checks. No FFI between the two (ADR 0000).

## How the port is checked
ADR 0000 prepared this switch; it pays off now:
- **Specs are the source of truth** (`docs/formats/`, `docs/re/`, `docs/render/`): the C++ code is written from them, the Rust code is consulted only where a spec is silent (and the spec is then fixed).
- **Language-neutral oracles decide.** The Python references in `tools/` (`chunks.py`, `tex.py`, `figuren.py`, `insel.py`, `sze.py`, `text.py`, `zei.py`) and the documented `anno-dump` text formats are the contract: the C++ `anno-dump` must print the same bytes as the Python tools on the whole corpus and on the synthetic files, exactly as the Rust one does today.
- **Corpus facts are in the specs** (counts, invariants); the C++ corpus tests assert the same numbers.

## Port order
1. **Skeleton:** CMake build, one library per former crate with the same dependency direction (`formats` ← `assets` ← `render` ← `app`; `sim`, `net`, `ui`), warnings as errors, sanitizer and format presets, CI for Windows (MSVC) and Linux (GCC, Clang).
2. **`formats` + `anno-dump`:** every reader/writer with round-trip, corpus and oracle-agreement tests (M1.1–M1.5 again, against the same evidence).
3. **`assets`, `render`, `app`:** the viewer, including the GPU compositor and the wave simulation, with the pixel-fidelity test (`docs/render/iso.md`, "Fidelity").
4. **M3 `sim`, M4 `net`** in C++ only.

## Proposed defaults (to be confirmed by the co-developer)
| Concern | Proposal | Why | Alternatives |
|---|---|---|---|
| Build | CMake ≥ 3.25 with `CMakePresets.json`, Ninja | the common denominator for MSVC, GCC, Clang; presets give one command per platform | Meson, Bazel |
| Dependencies | none in `formats`/`sim`; others via CMake `FetchContent` with pinned tags (vcpkg manifest later if the list grows) | `formats` and `sim` need only the standard library; pinned sources keep builds reproducible | vcpkg, Conan |
| Tests | doctest (single header, fast to compile) | small, no build step, CTest integration | Catch2 v3, GoogleTest |
| Errors | return values (adopted as `anno::formats::Result<T, E>`, errors mostly `std::string` messages), no exceptions in `formats`/`sim` | explicit, as the Rust code; deterministic control flow | exceptions, `tl::expected` |
| Window, input, audio | SDL3 | mature, Windows/Linux, C API | GLFW + miniaudio |
| GPU | WebGPU through `webgpu.h` (wgpu-native or Dawn) | the existing WGSL shaders (`gpu.wgsl`, `fluid.wgsl`) and the compositor design carry over unchanged; Vulkan/D3D12/Metal backends | SDL3 GPU API (needs shader cross-compilation), bgfx, raw Vulkan |
| Networking (M4) | GameNetworkingSockets or ENet | reliable UDP for lockstep | own UDP layer |
| Style | `.clang-format` (LLVM-based, 4 spaces, 100 columns; adopted, checked in CI with clang-format 23.1.3); `clang-tidy` with `bugprone-*`, `cppcoreguidelines-*`, `modernize-*` (proposed, **not set up yet**) | consistent, enforced in CI | — |

## Decisions since (2026-10-17/18)
- **Window, input, audio: SDL3** — confirmed by the owner. Pinned source SDL 3.4.18 via `FetchContent` (SHA-256 of the release asset in `CMakeLists.txt`), static; `-DANNO_SYSTEM_SDL=ON` uses an installed SDL3, `-DANNO_BUILD_VIEWER=OFF` builds without a window (headless `--png` only).
- **Colour reference:** the 24-bit palette colours; the original's 16-bit quantisation is not reproduced (owner, OQ-030).
- **GPU implementation of WebGPU: open.** Recommendation: wgpu-native (the engine the Rust viewer uses, so the shaders and compositor are already tested on it; prebuilt binaries for Windows and Linux). Alternative: Dawn (Google; larger, built from source). Both implement the same `webgpu.h`, so switching later changes the build, not the renderer.

## Rules that change
- The project rules in `CLAUDE.md` move from Cargo/clippy to CMake, clang-format and the sanitizers (clang-tidy once it is set up); the substance stays: evidence only, explicit field-by-field serialization (no `reinterpret_cast` of file data, no struct dumps, fixed-width integers), determinism in `sim` (integer/fixed-point, no `std::unordered_map` iteration, no floats in checksummed state, `/fp:strict` / `-ffp-contract=off`), no hardcoded limits, tests before refactors.
- C++-specific additions: no undefined behaviour (UBSan and ASan in CI), no `long`/`size_t` in file layouts, `std::span<const std::uint8_t>` for byte input, no global mutable state in `sim`.
