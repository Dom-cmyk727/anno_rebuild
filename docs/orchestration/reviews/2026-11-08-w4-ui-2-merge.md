hit them.

On this PC the same subsystem also stalled the game-file run at `96de6bca` twice (section 3, attempts 1 and 4).
- Test clients held their coordinator connections, made no progress and were never refused, despite
  `ANNO_TEST_ADMIT_WAIT_S=3600`.
- The second time, the journal showed nothing outstanding, and both the test and the coordinator's PowerShell host
  meter were idle.
- Both stalls ran under the same coordinator instance and the same meter process (pid 65816, started 2026-11-08
  19:22:27). A fresh coordinator ran the same test at once.
- A hang in the coordinator↔meter reading path fits what was seen, but it was not proven. In particular, a waiting
  request whose meter never answers would also never hit its client's deadline, if the deadline is checked only on an
  answer.

**Two more observations:**
- Large tests that take no reservation, such as one `anno_app_tests` case at 6.7 GB, lowered free memory enough for
  the coordinator to refuse reserving tests (`low-memory stop` with `pending=0`).
- Claude Code's background-task memory limit stops a full run on this 31 GB PC before the coordinator's own 4 GB
  headroom is reached. The full run must therefore be a detached process.

The follow-up covers the CI flakes, both stalls and these two observations.
