## What failed and what changed

Main inherited nonportable tests from the consolidated baseline: missing direct standard-library
includes, copied structured bindings rejected by GCC, signed counter literals, and unchecked
repeated nullable lookups. Those cases compiled on the local Mac but failed other compilers or
optimisation levels. Fixes add the proper includes, references and checked local pointers while
retaining assertions. The initial Ninja failures hid further errors: the first repair CI exposed
more GCC test warnings. Those failures remain in the record.

The only production change is in `script_runtime.cpp`. A script transaction now retains a checked
reference to each player when staging its changes and uses that same target during commit. It no
longer re-resolves a nullable player pointer and dereferences it unchecked. These references exist
only within the synchronous transaction; no supported handler changes the player-table slot storage.
Money and permission updates still compose in either order, and rejected transactions retain the
previous rollback behavior. No reference enters saved state.

Four fresh-process replay consumers had no truthful handling for CI's unavailable original files.
Economy consumers now use the existing asset-aware replay wrapper. Both SCRIPT2 modes require the
original permission program; “synthetic” describes their world, not an asset-free script. An
unset/empty game directory produces the existing explicit prerequisite skip. A declared invalid
directory remains a hard failure. Public-CLI controls cover both modes and prevent pretending that a
child ran. CI continues its pre-existing no-assets policy; these skips are not gameplay passes.
Asset-present execution is proved separately below.

one failure, 293 declared skips, zero sanitizer reports. No competing socket owner or errno was
