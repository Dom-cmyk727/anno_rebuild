## Permission and construction policy

Permission rows are sorted sparse exact-type overrides. Native storage uses widened u32 type and u32 value constrained to 0–255. Original ANLTRG records remain `{u16 type, u8 value, pad}`. Import validates whole records and known references, merges in record order with last duplicate winning, preserves absent versus explicit zero, and performs no setter grants.

A stored nonzero override allows; stored zero denies, even after a stage was unlocked. Without an override, the reviewed stage/research predicate applies. The reusable raw setter stores only the low byte but grants stage/research effects only when the full input equals 1: raw 257 stores 1 without granting. Individual script actions use TRUE/FALSE. Later denial does not remove a previous sticky grant.

Ordinary stages directly OR their bit; this is not population's extra bit-26 propagation. Stage 31 always marks the type's base research ID, including zero, plus separately declared output-0 research grants in the original category. It does not grant output 1 merely because eligibility can query it. Mandatory base grants and bounds were independently corrected/reviewed at `21631a7e`.

ALL selects eligible types for one mapped player, using original folk membership and HEAD exclusion facts, in ascending type order. It is not every player or every registry entry. Individual setters bypass the bulk filter. Sealed per-folk indexes and exact-row lookup avoid world/city/figure scans per eligibility query. Mapping resolves once, with the configured neutral-player fallback only when it exists; native reload validates actual persisted bindings instead of silently rebinding.

BuildCmd checks current authoritative state at apply time after existing site/ownership/structural validation and effective-type resolution, before optional research checks, serial allocation, payment, draws or writes. It checks requested type first, then effective type when different. One shared helper serves live and atomic application. Stale preview permission cannot authorize a later-denied command. Refusals leave canonical state unchanged; sequential-prefix and atomic policies retain their existing meanings. Supported roads are checked using tile outcomes rather than requiring a BuildingId. Founding, original import and automatic house transitions remain separate creation paths.
