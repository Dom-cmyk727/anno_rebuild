# `data/ui/` — derived in-game UI layout (UI.1)

Machine-readable facts about the original's in-game UI. **Derived only:** ids,
coordinates, sizes, file names, ACCESS names, frame/segment indices, `Texte.dat`
section names and line indices, Anlagen type ids, hotkey codes. Never original
pixels, decoded images, or UI strings (`docs/re/ui.md`, packet UI.1).

The files are generated by `python -I tools/ui_layout.py write-inventory --game-dir
<game/app> --out data/ui`. Re-running over the same GOG 2.0.0.5 files must be
byte-identical.

## Grammar (all files here)

Line-oriented ASCII. Bytes outside HT, LF, CR and 0x20–0x7e are refused. CRLF
and LF are equivalent (a trailing CR is stripped). Blank lines are ignored. A
line whose first non-whitespace character is `#` is a comment. Line numbers
count every physical line from 1.

The first content line is a version line, `anno1503-ui-<kind> 1`. Fields are
separated by one or more ASCII spaces or tabs. A field that may contain space
or `\` is a quoted string in the `tex.py` dump alphabet: `"` … `"`, bytes
0x20–0x7e except `"` and `\` as themselves, every other byte as `\xHH`.

Integers are decimal, non-negative unless the field says signed. `-` as a
whole field means “absent”.

## Files

| File | Version line | Contents |
|---|---|---|
| `dat.txt` | `anno1503-ui-dat 1` | Every `[TEXTURE]` ACCESS record in `Data/*.dat` that names a `.tex`. `segments` is `-` or one or more integers from the file (not truncated) |
| `inc.txt` | `anno1503-ui-inc 1` | Every `ToolGfx/*.inc` ACCESS record, with texture width/height when the matching `.tex` parses |
| `groups.txt` | `anno1503-ui-groups 1` | Filename groups with evidence (a `Data/*.dat` `[FILE]` pointer, or a stem that is a documented HUD/construction graphic) |
| `hud.txt` | `anno1503-ui-hud 1` | Pixel rectangles at 1024 x 768 for the HUD and build-test surface, each naming the screenshot and the method (sprite-sad, pixel-row, atlas-right) |
| `construction.txt` | `anno1503-ui-construction 1` | Construction-menu categories, `THUMBNAIL*` / `TOOLTIP:BAUMENU_*` binds, and every cell id from `View.dll` tables plus HEAD costs |

`write-inventory` rewrites only `dat.txt`, `inc.txt` and `groups.txt`. `hud.txt`
is measured from Wine-runner shots (`docs/re/ui.md` section 7). `construction.txt`
cell ids come from View.dll 8-byte tables plus Anlagen.dat HEAD costs; occupancy
and confirmation shots are from the runner. Inventory reruns leave both files
byte-stable.
