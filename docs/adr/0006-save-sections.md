# ADR 0006: Optional features add state without a new state number; pins regenerate by one command

- **Status:** **Accepted by the owner, 2026-11-13** ("Approve it", as proposed). Drafted the same day by the Claude Code
  orchestrator at the owner's request. Not implemented yet: PINS-1, SAVE-SECTIONS-1 and FIXTURES-TRIM-1 come first.
- **Date:** 2026-11-13
- **Evidence:**
  - the [MAP-INTEGRATE-2 review](../orchestration/reviews/2026-11-12-map-integrate-2-review.md), finding E1;
  - the [project analysis](../orchestration/reviews/2026-11-12-project-analysis.md) §3.2 item 5;
  - the code read at `main` `961a9d4a` (`state_fields.hpp`, `world.hpp`, `replay.hpp`) and
    [`docs/sim/state.md`](../sim/state.md) §9.

## Context

**How the state is identified today (C):**
- **One field list.** `fields(T)` names every persistent field, and saving, loading and hashing all run it, so a field
  cannot be saved and not hashed (`state_fields.hpp`, header comment). That is right and stays.
- **One global number.** The stream begins with `kStateHashVersion` (138), the PRNG timeline version (5), `SimConfig`,
  `Rules` and the registry digest. Adding any field, even one optional rules flag, needs "a `kStateHashVersion` bump and
  re-baselined goldens in the same commit". Saves and replay logs of every older number are refused.
- **The save frame is already sectioned:** "A3SV", the save version, `kStateHashVersion`, the PRNG table kind, the
  sections **each with its byte length in front**, the terrain blobs, a checksum (`StateIO::save`; `state.md` §9.5).

**What it costs (M, 2026-11-13):**
- `fixtures/synthetic/sim/` holds **387 files, 31.7 MB**. A near-identical golden set of about 1.8 MB exists per
  state number: `consolidated132`, `econbook1`, `salt1`, `iron2`, `freight`, `integrate2/current138`, and more.
  `integrate1` alone is 12.3 MB.
- **126 hash values are hard-coded in 30 sim test files.** `scenario_corpus.txt` pins every scenario's hash.
- **No single tool regenerates them.** A few fixtures have their own `--check`/`write` scripts.
- **Two features built side by side can't be combined without a new "union" number** and a full re-recording.
  MAP-INTEGRATE-2 took 13 hours; E1 was its second cause.
- **The owner's rule of 2026-11-12 therefore holds every packet that adds state:**
  - the wildlife port (WILDLIFE-1);
  - the whale port;
  - the fisher port (FISHER-1b);
  - EDITION-2;
  - freight through the effect queue (E2–E4).

  A fisher switch alone would need a new number, because every `Rules` field is saved (`fields(Rules)`: `city_booking`
  took "stream133", the freight rules "route-only136").

## Decision (proposed)

1. **Optional features keep their state in tagged extensions.**
   - Each stream section ends with an **extension list**: entries `(u16 tag, u32 length, payload)`, sorted by tag.
   - Each payload is written by its own explicit `fields(...)` function (no struct dumps, no macros).
   - **An extension is written only when its content differs from its default.** A feature switched off writes
     nothing, so its absence means the default.
   - **Where a feature's parts go:**
     - its rules flag, in the `Rules` (header) section's extensions;
     - its per-figure, per-building or per-island state, in that section's extensions;
     - its PRNG draw sites, declared under its tag, drawing only when the feature is on (as the House sites do today
       under `house_updates`).
2. **Consequences of the extensions:**
   - **A default-off feature changes no existing hash, golden or save.** A world with the feature off writes exactly
     today's stream.
   - **Two features combine by having two tags.** No union number is needed.
   - **A save loads into a newer build that knows more tags.** Absent tags are the defaults.
3. **Unknown or invalid extensions are refused, never skipped.**
   - **Loading:** an unknown tag is refused with its number and section. Determinism forbids simulating state the build
     doesn't understand.
   - **Multiplayer:** the join check (ADR 0003, amended as ADR 0005 already requires) compares a **schema
     identity**:
     - the base version of each section;
     - the PRNG base timeline;
     - the tags this build knows;
     - the active rules.

     Peers that differ don't start.
4. **Each section carries its own base version.** The single `kStateHashVersion` becomes a list:
   - one version per stream section (header, clock_rng, settings, ids, players, islands, figures, events,
     timers_monopoly);
   - plus the PRNG base timeline.

   A base version moves only for a change to a section's **base** layout, or to **default** behaviour; a load error
   then names the section. A change to default behaviour still moves the hashes, which is honest, and paid by item 5.
5. **Pins are data, regenerated by one command.**
   - **Where they live:** every pinned hash or golden value lives in **one pins file per area**, for example
     `fixtures/synthetic/sim/pins.txt` (name → value), and the tests read it. No literal hashes remain in test sources.
   - **The command:** `python -I tools/pins.py regen [--area sim]`
     - runs the tests in record mode;
     - rewrites the pins files;
     - re-records the replay-log goldens **in place**;
     - prints one summary of what moved.
   - **The check:** `pins.py check` is the CI check that the committed pins match a fresh recording.
   - **The review:** a reviewer sees one diff, and the reason for every moved pin is the commit message's job.
   - **The independent oracles stay independent:** `tools/sim_stream*.py` and the reference scripts are not
     regenerated from the C++. A pin that one of them holds is compared, not overwritten.
6. **One fixture set, no copies per number.** The goldens of the current schema live in one directory; git keeps the
   history. The per-number copies (`consolidated132` … `integrate2/current138`, `integrate1`'s legacy part) are deleted
   once the current set covers what their tests prove (FIXTURES-TRIM-1, parked until now).
7. **Old saves while the game is in development:** a save of an older *base* version is refused, as today, with the
   section named. Migration code begins with the first public release, not before. An *added* tag never invalidates a
   save (item 2).

## Consequences

- **The last global renumbering.** Introducing the extension lists and the per-section versions changes the stream
  once (138 → 139), and every golden is regenerated once, by the new command. After that, default-off features cost
  no number.
- **What the held ports become:**
  - **wildlife, whale, fisher:** tags behind default-off rules flags; each lands alone, in any order, without moving a
    golden;
  - **EDITION-2:** it *removes* `city_names` from the hashed `Rules`. That is a base change, so a base version moves
    and the pins regenerate by the command;
  - **freight E2–E4:** a change of default behaviour, so a base version moves too, paid the same way.
- **Switching a feature's default on** (the owner's call, as for the living town) moves the hashes of every state that
  now contains the feature. That is correct, and regenerated by the command.
- **Cost of the mechanism:**
  - one extension list per section in the archive, with explicit `fields()` per payload, so the "one field list"
    rule holds per extension;
  - a tag registry in `docs/sim/state.md`, reserved like OQ numbers, so parallel packets never collide;
  - the hash tree (`hash_tree.hpp`) shows an extension as its own sub-scope, so a divergence names the feature.
- **The registry digest** (in the header) still moves when type data is read differently, for example the fisher's
  figure kind. Synthetic goldens use synthetic registries and are unaffected. The real-file pins regenerate by the
  command.

## Work (each one packet, Windows lane unless stated)

1. **PINS-1:**
   - `tools/pins.py` and the pins files;
   - the 126 literal pins and `scenario_corpus.txt` moved into them;
   - the replay goldens re-recorded in place by the command.
   - **Proof:** `pins.py check` passes, a hand-edited pin fails it, and no test asserts a literal hash.

   This comes first, because it makes the one renumbering cheap.
2. **SAVE-SECTIONS-1 (139):**
   - extension lists and per-section versions in the archive;
   - the tag registry;
   - unknown tags refused;
   - all goldens regenerated by `pins.py regen`.
   - **Proof:**
     - a synthetic extension round-trips;
     - it changes the hash only when present;
     - a world without it hashes identically before and after it is registered;
     - an unknown tag is refused, naming its section.
3. **FIXTURES-TRIM-1:** the per-number copies deleted, and their tests pointed at the one current set. Measured: the
   bytes saved.
4. **Then, in any order, each with its own tag:** FISHER-1b, WILDLIFE-1, the whale port (Mac or Windows). EDITION-2
   and freight E2–E4 are base changes, paid by the command.

## Questions for the owner

**Answered by the approval "as proposed" (2026-11-13):**
1. The extension mechanism is accepted: a default-off feature never moves a golden and never invalidates a save.
2. During development, a save of an older base version is refused, with the section named. Migrations begin with the
   first public release.
3. The per-number fixture copies are deleted once the current set covers what their tests prove (FIXTURES-TRIM-1).

The questions as they were put:

1. **Accept the extension mechanism** and its rule: a default-off feature never moves a golden or invalidates a save?
2. **Old saves during development:** refuse older base versions (recommended), or start migrations now?
3. **Delete the per-number fixture copies** once the current set covers them? About 15–20 MB, an estimate from the
   directory sizes above; FIXTURES-TRIM-1 measures it.

## Not decided here

- **The PRNG timeline of default behaviour:** porting a draw site onto the default path still moves the base
  timeline, as today.
- **ADR 0003's network transport,** beyond the schema identity that the join check compares.
