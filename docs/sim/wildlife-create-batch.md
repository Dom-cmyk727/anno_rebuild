## Input, effect and admission boundary

Source: accepted completed prepared terrain/import/maintenance/materialization,
selected sealed descriptors and source geometry. Supplied: numeric profiles,
per-token manager Success/Null, successful assigned id/creation time, outcome
provenance. Unknown: imported/fresh prior id/high bit/byte11, native allocation,
callback effects, runtime CW and global interleaved draw history.

Materialization already computed selectors. Keep prefix/maintenance/selector-only
counts and unused suffixes unchanged even when creation later refuses. Never call
this a newly executed native interleaved PRNG history. Geometry consumes existing
position outcome; no new draw. Source/descriptor preparation is whole-batch
admission before effects; missing/invalid reached manager or numeric facts fail
with owned completed prefix and exact token/stage. No native rollback claim.

Factor the existing known-input creation projector through one shared outcome
implementation that emits only proved field writes. Null never needs success-only
id/time in the new optional context. Legacy complete-input validation/error order
stays unchanged. Apply writes to optional maintained fields without constructing
fake packed bytes; preserve position/high-bit/byte11 and resources/typed sidecars.

Share the existing empty-cleanup state transition and original home lookup rule
with a narrow optional-record release adapter. Resource fields are never read as
spawn facts. First category0/local-position match clears occupancy regardless of
saved ID; missing needed positions refuse as adapter admission, not a guessed match.
No moving/live/nonempty cleanup, destructor, allocator or first-action expansion.

Tests may add explicitly authored occupied runtime snapshot facts to the synthetic
prepared fixture, then use the existing materializer; those are not claimed imported
file occupancy. The original Tutorial case remains unchanged and has no such overlay.
At B0 all new implementation/gates NOT_RUN. No expected results generated from C++.

## Implemented conditional interface

`prepare_wildlife_create_batch` binds ordinary source geometry once and walks the
completed materializer's existing record order. It owns per-entry prior facts,
manager provenance, descriptor and geometry, plus the updated optional-record
chunk, typed resource sidecars, source identity and unchanged draw domains/suffixes.
Missing manager outcome is distinct from supplied Null. Null needs no assigned id
or creation time; successful id/time zero remains a known value. The shared
`project_wildlife_creation_outcome` returns animal/stages and success-only field
writes. The legacy complete-record projector uses the same core while retaining
its original pre-Null id-range validation. No prior packed byte is synthesized.

Whole-batch order/accounting/descriptor/source admission has no executed prefix.
Later manager/geometry/projection failures own a diagnostic completed prefix and
failing token; they are neither successful partial batches nor native rollbacks.
The already materialized selector counts still describe the complete input plan,
not only the returned prefix. No manager callback or new random draw executes.

`release_island()` derives the narrow end adapter's island/chunk headers from the
same source. Both end adapters share one bounded state transition. The optional
adapter changes only the first matching category-0 record's occupancy; it retains
unknown id/high-bit/byte11 and resource records. Typed sidecars remain owned
unchanged in batch progress, outside the release adapter. A different saved id is
not a veto. Repeated detached end does not clear replacement occupancy. A needed unknown
position refuses; an unknown position after the first match is never inspected.
This remains empty-cleanup attached ordinary end, not movement/death or arbitrary
native cleanup. Numerical profiles, manager outcomes and live-corner provenance
remain supplied facts. Native CW/allocator and live World integration stay open.
