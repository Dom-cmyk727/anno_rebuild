What the artwork can and cannot prove

The requested [https://www.annoinfo.de/Anno_1503/produktionsketten.html] Annoinfo production-chain page is a useful visual index. It is not a complete simulation specification. All 39 linked chain pictures were inspected; 78 observed page images were exported through the browser for local comparison. Facts about the local build below come from the game files and RE notes, not from silently treating diagram arrows as executable rules.

P — parsed now: fields, IDs, offsets, hashes and decoded images read from the local original files. D — inherited disassembly evidence: original-module addresses recorded in the repository RE notes; this task did not rerun the original executable or re-disassemble every function. H — original help: shipped HTML/text, which can retain obsolete content. W — website: the requested community diagrams, individually inspected. R — recommendation: proposed project architecture or a future verification task. These categories are not interchangeable.
Separate an icon, a help portrait, a world sprite and a production rule. They may show the same building while having different sizes, palettes, offsets, animation structure and validity. Visual language and design implications

P, visual observation: inspected native icons and portraits use small rendered objects on framed, textured backplates. Materials remain legible through silhouette and characteristic color: cut timber’s round ends, fibrous wool, ore fragments, cloth folds and recognizable weapon shapes. The icons carry material detail rather than abstract single-color pictograms. Muted stone/metal backgrounds and brighter objects provide separation; tiny labels should live outside the image, not obscure its silhouette.

Buildings combine timber, stone, roof surfaces, work yards and function-specific equipment. Mills advertise moving sails; smiths and furnaces use chimneys and industrial equipment; plantations combine a small central building with separately placed growing fields. The production building’s tile footprint does not include every visible protrusion, and its catchment is not its sprite rectangle.

R: retain recognizable original silhouettes, palettes, proportions and material cues in faithful mode. Modern UI can supply sharp typography, scalable panels, tooltips, status overlays, accessible redundant markers and clear input/output diagrams. Keep a unit’s player color, selection, damage and shortage indicators in explicit channels so they do not become ambiguous resource identities.

Large website pictures are primarily 1024-pixel-wide diagram canvases arranging multiple illustrations. They are not evidence that every source building has a 1024-pixel world sprite. The original ToolGfx resource icons in this crosswalk are 50×50. Many building-help textures are 102 pixels wide with taller canvases; some have only the top portrait populated. A filename ending in “8” and a tall help canvas do not establish a world zoom level or seven useful animation frames.

Original files and the runtime asset path

 | Layer | Original source / key | Correct use

 | Economy identity | Anlagen.dat / ANLAGEN / ENTRY id; WARE, ROHSTOFF, PRODTYPE | Join by stable IDs and canonical names, not by a translated filename.

 | Help resource icon | ToolGfx/*.tex, companion .inc INCACCESS | Decode texture ID and palette. The crosswalk is semantic; a runtime UI-binding table is not newly traced here.

 | Help building portrait | ToolGfx/Forsthaus.tex, Muehle.tex, etc. | Use as encyclopedia/menu art. Do not place the portrait’s frame in the world.

 | World building layers | Anlagen.dat / HAEUSER / ENTRY / GFXDATA, ANIM and frame headers | Select the correct sprite set/frame and zoom; preserve anchors and animation state.

 | Palette | Anlagen entry palette_ids and global color tables | Frame palette is an index into the entry’s palette-ID list, not a global palette number.

 | Pixels and depth | TEXTURES group volumes; RGBZ/AZ family | Decode color, coverage and per-pixel depth; retain special checkerboard/depth-blend semantics for faithful composition.

 | Shadow | Separate SHADOW sets where present | Composite with the original rules; don’t bake an invented drop-shadow into every atlas sprite.

 | Growing fields / workers | Anlagen resource entries; FigurenHeader.dat + Figuren volumes | Animate and position separately; a plantation portrait is not a complete farm scene.

 | Terrain / suitability | Felder.tex, island HEIGHT/GFXID; Data/Wachstum.dat | World terrain and crop suitability are distinct from UI resource art.

Modern performance without losing original appearance

D: the existing asset corpus specification records 28,899 Anlagen frame decodes with no failures, and a shared CPU/Rust RGBA digest 4d53061488caa2b0. That is prior repository evidence, not a fresh full render run in this task. This task freshly parses all 921 records and decodes selected source frames and UI textures.

Preserve the original alpha levels (64, 128, 191, 255), signed anchors, palette selection, special pixel modes and depth. Some original runs write beyond the frame’s declared width; widening the decoded image preserves those pixels. Atlas packing based only on the header rectangle can clip artwork. A flat RGBA thumbnail intentionally omits depth; it is useful for inspection but cannot serve as the complete faithful compositor reference.

R: decode immutable content on workers, reuse shared sprite/texture/depth data across world instances, and cache by complete source identity and decode configuration. Atlas or texture-array placement must preserve transparent gutters and avoid color bleeding; bound residency and measure reclamation. Batch GPU draws by compatible state while preserving the original compositing order. Cull by actual visible extents, not solely building footprint.

R: animation should select existing frame data rather than rebuild entire island content. Place/demolish updates should invalidate the affected geometry and pixel bounds, including all zooms and neighboring overlap; unrelated cities should not cause whole-scene work. A frame must retain every generation/resource it reads until GPU use completes. Backpressure, stale completion rejection, cancellation and delayed reclamation are part of correctness, not just optimization.

R: assess 1080p and 4K presented-frame time under panning, zooming, mass construction, animations, weather/water and active city logistics. Report CPU preparation, chunk rebuilding, uploads, GPU work, waits and memory separately, plus end-to-end p95/p99/max. A fast object-list stage does not demonstrate a smooth displayed frame. Follow the project’s PLAN §0.3 targets and run Windows/Linux, RTX and Radeon gates when those hosts are available.

Faithful mode should use the original art and documented compositing. Enhanced water, higher-resolution replacement art or modified shading can be separate selectable layers. Upscaling a 50×50 icon may make it larger; it does not recover authoritative original detail.
