How production actually advances

D: [/Users/dom/Dev/anno1503-worktrees/anno1503/docs/re/production.md] Original production traces and [/Users/dom/Dev/anno1503-worktrees/anno1503/docs/sim/production.md] their integer simulation specification. The general type loader is AnnoGame.dll 0x10009240; the PROD3 conversion is 0x10009627–0x10009717. Source values are read from IEEE-754 fields once; deterministic simulation then operates on integers.

Stock:       256 fixed-point units = 1 tonne
World time:  1 tick = 2 game milliseconds; 500 ticks = 1 game second (docs/sim/core.md)
Step gate:   if uint16(t − last) < 500: return; otherwise last += 500

q0 = 256 / T0                  output0 = trunc(q0 + 0.5)
q1 = 256 / effective_T1         output1 = trunc(q1 + 0.5)
need0 = trunc(q0 * I0)          need1 = trunc(float32(q1) * I1)
effective_T1 uses T0 when T1 is zero (also NaN in the original loader).
Display rate = trunc(display_float * 256); it is a separate field.

Generic workshop, full step:
ratio = min(128, (input_stock[i] << 7) / need[i], for each active input)
ratio < 64 → missing input; output already at capacity → storage full
made = output0 * ratio >> 7
consumed[i] = need[i] * ratio >> 7

The gate advances one step per visit, not an arbitrary elapsed-time multiplier. Preserve switch/suspension checks, status order, rounding, reservation ownership and event order. A partial input ratio can still produce; a full output buffer blocks. A file’s display throughput must not be substituted for the integer converter. The world-clock interpretation follows docs/sim/core.md (AnnoWelt.dll 0x100ae040 and world property 7); it describes game time, not a guarantee of wall-clock throughput under load.

Worked example — Webstube 1001: T0 = 43, I0 = 1.84765625. The loaded converter produces 6/256 t and consumes 11/256 t WOLLE per fully supplied step. Its ideal converter ceiling is 1.40625 t/min output and 2.578125 t/min input. The stored display value is 1.3671875. Sheep farm 807 has a 6-unit converter output, so a diagram’s one sheep farm cannot be certified as a full-fed source of an 11-unit demand from those numbers alone; worker travel reduces actual supply further. This is a converter calculation, not a measured gameplay rate.

Worked example — Bogenmacher 1006: both unlocked lines use share 64/128 and make 4 bows plus 4 crossbows fixed units; a single working line makes 9. If any line produces, the full input ratio consumes 8 wood and 4 rope fixed units. Output-0 capacity governs both lines. Independent, full-speed icon recipes would be wrong.

Deposits: the documented deposit object starts at 2,000 t. With its reserve flag set, a shallow iron mine stops when 1,600 t remains; a deep mine can extract without reducing that reserve. Without that flag it takes at most the remaining amount. Depletion is also controlled by the ANNOADDON1 edition flag, not a newly invented owner difficulty option. The mine chooses the greatest remaining deposit in its documented radius-7 search, retaining the first on a tie. These distinctions matter in long matches and need save/load fixtures.

Precision and original defects: existing corpus analysis gives the same load integers at x87 53- and 64-bit precision. At 24-bit precision, entry 1010’s second input differs (6 versus 7); OQ-032 remains open. The small farm’s 75,000-tick status interval exceeds its 16-bit elapsed range, so that message cannot fire in faithful behaviour. Any correction belongs in a named rules option, with a compatibility test.

Land, growth, workers and transport

Natural island differences are part of the game. A crop chain depends on suitability and available land, not just equal island area. The MAP checker’s attached-land estimate is not a fertility map or a proof that a five-city economy works. No fairness rule or candidate choice is made here.

Growth: AnnoWelt.dll 0x1008b5f0 advances growing objects using a sampled phase bit. With S = HEAD[0x10], k = HEAD[0x18] and time0_128 = trunc(T0×128), the period is time0_128×1000 / (2^k×S×128), stored in 16 bits. This applies to growing entries with S ≥ 2, not all buildings. Grain 712→713 needs 20 phase flips of t/7750, nominally 155,000 ticks (310 game seconds). Chunk visits can miss flips; some original periods wrap. Replacing this with a smooth real-time progress bar as the simulation would change outcomes.

Fertility: AnnoWelt.dll 0x10084370, the climate table at 0x100ca008, Data/Wachstum.dat, Data/Felder.dat and HEAD byte 0x19 provide evidence for terrain/crop suitability. The traced rebuild takes the terrain suitability p, blends it toward a nonzero raw-object HEAD value v with (p+3v)/4 when p<v or (v+3p)/4 otherwise, then combines rounded values through a climate-weighted 5×5 neighborhood into a 0–10 nibble. The remaining path from suitability to final harvest yield is not fully resolved by this report. A website “100%” label is not evidence of a universal linear yield multiplier.

Worker model: PROD3 contains three groups of count/limit/start bytes at 0x28, then nine u16 figure IDs at 0x32. FigurenHeader.dat gives worker classes and LOGIC data. Work area, walkability, building entrances, crop tiles and rendered sprite size are separate concepts. HEAD width/height cannot stand in for the entire service or harvest area.

Transport: [/Users/dom/Dev/anno1503-worktrees/anno1503/docs/re/transport.md] the transport traces record workshop-fetch jobs 0x33 and market jobs 0x34, with selection, loading and unloading. The search rectangle is centred on the footprint: x + (w−1)/2 − r; width 2r+1+(w−1)%2. It is not simply the footprint expanded by r on both sides. City ownership, producer output reservations, goods scoring, entrance routing and tie order all affect which resource is fetched. For raw warehouse goods, the market willingness score includes the 75%-capacity threshold. Carriers and carts use different source masks and path layers; carts use road layer 3, carriers open-land layer 0 in the documented paths.

Reservations are not cargo: reserved source output must be unavailable to other jobs, released on abort, and transferred only on actual load. The original warehouse add/remove routines at AnnoWelt.dll 0x1002da50 / 0x1002da90 clamp stocks. HEAD2’s capacity in tonnes (zero means 50) applies to each good, not to a 50-ton shared basket. Arrival at a full warehouse can lose overflow in the original; an improvement must be explicit.

Late-game bottlenecks: full buffers, roads, pickup cadence, worker travel, simultaneous consumer requests and shared intermediate goods can dominate conversion time. A correct late-game test must track the whole chain of ownership and inventory, not only run an isolated factory function repeatedly.

A manageable future implementation sequence

R: the following work packages preserve original outcomes while allowing large multiplayer cities. They are recommendations, not a new authorization to alter either executor’s branch.

Freeze a content contract. Read this report, docs/formats/anlagen.md, docs/re/production.md, docs/sim/production.md, docs/re/transport.md and docs/re/population.md. Load IDs, typed goods domains, rates, costs, thresholds and image references from data. Exclude unsupported legacy chains from the faithful ruleset. Hash the relevant rules and mod overlays for multiplayer.

Close worker and special-class gaps. Trace harvest/catch amounts, fertility effects, JAGDHAUS, WALFAENGER, quarry coupling, WERFT and KANONENBAU. Produce small original-game fixtures for one successful job, one failed job, cancellation and full output storage in each class.

Prove one complete supply loop. Start with tree → forester → warehouse, then wool → weaver → retail. Include walking, ownership, reservations, source depletion, blocked outputs and actual consumption. Track mass balance and original overflow explicitly.

Add shared and competing chains. Bread, two-input silk/clothing, dual weapons, mines/reserves and research gates. Verify exact rounding, original event/PRNG order and save/load at mid-job boundaries. A table-derived recipe test alone is insufficient.

Build legal city workloads. Use real registry placement, roads, warehouses, workers, consumption and a reproducible command stream. Test five and eight players, natural island differences, inter-island shipping, shortages and surpluses. Report legality separately from approximate geometric map suitability.

Measure scaling. Hold one active city constant while growing unrelated cities. Track tick p50/p95/p99/max, active jobs, traversed cells, path requests, queue waits, memory/high-water marks and deterministic checksums. Use stable spatial/ownership indices and dirty sets so cost follows active work, not every object on every tick.

Separate rendering from authority. Publish immutable sim snapshots. Parallelize content decode and independent render preparation; apply authoritative results in deterministic order. Measure end-to-end presented frames, not just a worker’s rebuild time, under active logistics and large cities.

Gate optional improvements. Any revised yields, faster workers, overflow handling, fairness guarantees, restored paper/books or changed original bugs require a named rules option and separate fixtures. Modern scheduling, memory safety and caching must not silently change the faithful economy.

Use the host’s measured safe concurrency and shared memory-admission mechanism. Keep rendering-heavy runs out of early correctness iterations; run cheap contract negatives first, then focused sanitizers, then full and target-host gates once the candidate stabilizes. Store raw samples, seeds, code/content hashes, skip reasons and exit statuses.
