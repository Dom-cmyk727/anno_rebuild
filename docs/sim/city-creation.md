## 2. Cursor identity (B2)
`ring+0x40` (dword, **allocation cursor = last added slot**) and `ring+0x46` (byte, **scheduler cursor**) are different words *(constructor `0x10096da0`: `+0x40 = -1`, `+0x46 = 0`, `+0x44 = 0`, `+0x47 = 0xff`, `+0x48 = 0`; reset `0x100967b0` sets `+0x48` the island, `+0x44` the stamp, `+0x46 = 0`, `+0x47 = 0xff` and does not touch `+0x40`; the scheduler `0x100969d0` uses `+0x44`/`+0x46` only; removal `0x10096990` changes `+0x47` only)*. `Island::ring.cursor` is the scheduler's and is neither read nor written by city creation; `Island::city_cursor` is new. The engine has no city removal; when it gets one it must leave the allocation cursor alone.

## 3. Initialization (B3)
- Empty island (fresh object): `city_cursor = -1`.
- Loaded island with cities: after the load `city_cursor` = the number of the **last city created in load order**, gaps legal, never inferred from the highest occupied slot. REQUIREMENT: the scenario spec lists each island's cities in file order (the adapter appends them so); the existing creation loop sorts by number, so the cursor is taken from the spec's LAST entry, not from the sorted order. An island with no city keeps `-1`.
- Highest-used metadata: derived (E4), never stored.
- Names: see E6. Names are not read from files (no decoded source record; `docs/formats/insel.md` lists an island record `STAEDTE` that may be the list's source: OPEN), so `City::name` is empty for loaded cities.
- Kontor counter: default 1; loaded value = the `KONTORID` record's u16 when present.

## 4. Refusals and their order (B4)
`create_city` is `prepare` (const: no mutation, no live PRNG advance) then `commit`. Prepare checks, in this order, each with its own refusal: `UnknownIsland` → `UnknownPlayer` → `InvalidMetadata` (stamp does not fit u16; `city_slots` zero or a `city_cursor` outside `[-1, city_slots)`) → `OwnCityOnIsland` (the owner already has a city on THIS island: P9, same player and same island only; another player's city, here or elsewhere, never refuses) → `NoCitySlot` (no usable slot) → `UnusableNameData` (an empty list; an entry containing NUL, any entry) → the name draw is PEEKED on a copy of the world generator. Commit re-checks what the peek and the slot depended on — the `WorldRng` cursor, the chosen slot still empty, `Island::city_cursor`, and the owner's city count on the island — and refuses `StalePlan` otherwise; only then does it apply E2, E3, E5, E6 and the single draw. The Kontor step (`prepare_kontor` / `commit_kontor`) is separate: `CounterOverflow` when the counter is `UINT32_MAX`, `StaleKontor` when the counter changed since prepare; nothing is incremented by preparing, previewing, failing, saving or loading, and the building serial counter is never used for it. `Island::kontor_counter` must be at least 1; `validate_islands` rejects 0 and a `city_cursor` outside `[-1, city_slots)`.

## 5. State and PRNG timeline (stream 119, timeline 3)
State: `Island::city_cursor` (i32, after `lock`), `Island::kontor_counter` (u32), `City::name` (string), `Building::kontor_id` (u32): `kStateHashVersion` 118 -> 119. Defaults `-1`, `1`, empty, `0`.
PRNG: two new draw sites, so the timeline is bumped 2 -> 3 (`kPrngTimelineVersion`, `tools/sim_stream.py`, `docs/sim/state.md` §6 and §14, the replay header manifest): `DrawSite::CityName` (D `0x10096910`; phase `Advance`, since a command applies inside the world step; ported; draws through `GlobalDraw`) and `DrawSite::CityNameLoad` (D `0x10096910` reached from the scenario loader, E15; phase `Load`; unported, listed in the manifest). `may_draw` keeps its meaning: a Load-phase site never draws in advance and vice versa, which is why the two are separate sites. A created city consumes exactly one table step when a name list is supplied and none otherwise. Goldens: worlds that create no city change only through the two version numbers and the added default fields; this is checked against `tools/sim_stream.py`.
