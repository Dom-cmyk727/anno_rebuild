## What was checked

- **The compiler** (`script.cpp`):
  - `OBJECT_STADT` keeps the low 16 bits, island = low byte, city = high byte, widened into `IslandId` and `CityNo`;
  - any other object kind or operand count still refuses;
  - an unknown name in `KILLED` refuses at compile time;
  - matching is whole-name ASCII case-folding (`upper()`), and the first declaration wins;
  - nothing in the world is read at parse time.
- **The duplicate-name switch** in `formats`: `allow_duplicate_object_names` is off by default, so the shipped-file
  uniqueness check and the corpus stay as they were. Only the script compiler turns it on, citing
  `AnnoScene 0x10023f40`.
- **Evaluation** (`script_runtime.cpp`): live per call; true for an empty slot; no stored result, no RNG.
- **The invalid domain:** a missing island or a slot outside `Island::cities` returns a host refusal, which the
  existing `ScriptFault::Host` path rolls back and the scheduler turns into a world fault. That is the review's
  decision, and `script-objects.md` §7 records it as a difference with both addresses.
- **No hardcoded limits:** the ring is `Island::cities.size()`, from `SimConfig::city_slots`; a 300-slot test ring
  reaches slot 255.
- **Saving:** `city_objects` comes from the program text and is never saved; no new field, section or version. A
  reload test founds a city in an empty slot and checks the live answers and the hash.
- **Tests:** 7 C++ cases drive all 13 SO-1a vectors. The base control swaps in `cc7af72c`'s `script.cpp`: five cases
  fail and the refusal control passes. The game-file case was run separately: the base refuses at the objects.
- **The canary step:** `S01_02_01` now refuses with `script offset 1339: unsupported action: QUESTLOG_SHOW`, as the
  packet asked.
- **Gates:** affected lanes 115 executed, 0 failed; pins 1682 executed, 0 failed, 0 pins moved.
- **F1 from the SO-1a review** is fixed: evidence letter P is in the legend.

## Finding (carried, not blocking)

- **F1:** the engine indexes `World::islands_` by the scenario's island number (`IslandSpec::slot`, from the
  `INSEL5` record). SO-1a proved that the original indexes by the island's number at `+0x98`, keeping only its low
  byte. The note does not yet show where `+0x98` is written from the file, so "the two are the same number" rests
  on the S01_02_01 corroboration alone (islands 4 and 18 found through the `INSEL5` rectangles). FISHER-1e's canary
  exercises this on a real map; before that, one addressed line in `script-objects.md` closes it. It goes into
  SL-0 as a small extra item.
