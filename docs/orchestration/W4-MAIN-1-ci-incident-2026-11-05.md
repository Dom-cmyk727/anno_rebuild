# W4-MAIN-1: WSL gate and cloud CI incident report — 2026-11-05

**For the orchestrator.** Covers two linked incidents from the W4-MAIN-1 merge gate: (A) the
local WSL ASan/UBSan gate's recurring false failures and multi-hour runtime, and (B) the
discovery that cloud CI (`.github/workflows/ci.yml`) has been red on every push to `main` for
some time, independent of this merge, plus the seven concrete bugs found and fixed to get it
green. Owner directive that started part B: stop the local WSL run, root-cause it, and move the
gate to cloud CI since local hardware contention was stalling other development.

## Part A — the local WSL ASan gate (6h17m, two false failures)

Full detail and evidence: `docs/testing/wsl-gate-root-cause-2026-11-05.md`. Summary:

### A1. Inflated "dirty" counts and a false "source changed during selection"

Git for Windows ships `core.autocrlf=true` machine-wide; WSL's git has no such override
(defaults to `false`). Both read/write the *same* `.git` directory and NTFS worktree. Windows
git checks text files out as CRLF; WSL git, with no conversion, compares those CRLF bytes
byte-for-byte against the LF blobs in the index, so roughly 1000 tracked files show "modified"
under WSL git on an otherwise pristine checkout. Confirmed present at the same magnitude
(523–545) in every prior WSL gate log since 2026-11-02 (`anno1503-W4-opening-1/cache/gates/wsl-w*.txt`).
It had already been solved once, in `cache/o1/wsl_gate5.sh`, by forcing WSL git's view of
`core.autocrlf` to match Windows' for the status check — `wsl_gate_m1.sh`, written fresh for this
merge gate, didn't carry that forward and regressed. The resulting ~1000-line noise buried a
real mid-run edit (a CRLF fixture fix applied to the worktree while the 6-hour script was still
reading it, against plan), which correctly tripped `run_selected.py`'s own "tested source
changed during selection" integrity guard on the render lane — the guard worked; the noisy
baseline made the hazard easy to miss. The sim/formats lanes' results from that run reflect the
pre-fix fixture state and can't be trusted either way.

### A2. The underlying fixture bug this exposed (fixed, commit `9e04c5a6`)

`src/sim/tests/founding_fixture.hpp`'s body-hash check and
`src/formats/tests/ship_manifest_test.cpp`'s exact-string field compare both choke on a trailing
`\r` that `operator>>`-based readers elsewhere tolerate. The committed bytes were always LF
(generated by `tools/founding_fixtures.py` on Linux); the corruption was purely a Windows-checkout
artifact, so a plain Linux clone (cloud CI) could never reproduce it. Fixed:
`.gitattributes` forces `text eol=lf` on `fixtures/synthetic/{founding,map2_manifest,sim}/**`, 29
files renormalized, and `founding_fixture.hpp` strips a trailing `\r` defensively.

### A3. Why the gate took 6h17m: GPU tests silently ran on the wrong, slow adapter

`wsl_gate_m1.sh` builds with `-DANNO_BUILD_GPU=ON` and runs the full `anno_render_gpu_tests`
suite without setting `WGPU_BACKEND`/`VK_ICD_FILENAMES`/`ANNO_REQUIRE_GPU`. The log confirms the
adapter actually used: `adapter: llvmpipe (LLVM 19.1.1, 256 bits) (Vulkan)` — Mesa's CPU software
rasterizer, not the RTX 4090 or the Radeon iGPU, and not `lavapipe` either.
`docs/testing/gpu-tests.md` already documents the correct setup (install
`mesa-vulkan-drivers`, then `WGPU_BACKEND=vulkan`, `VK_ICD_FILENAMES=.../lvp_icd.json`,
`ANNO_REQUIRE_GPU=1`), used by CI's `linux-gcc` job; `wsl_gate_m1.sh` never applied it. Measured
wall-clock: build 3.9 min, app 133.8 min, sim 29.4 min, formats/assets 20.5 min, **render
182.6 min**, test_support 6.3 min. `docs/testing/gpu-tests.md` records the same GPU case sum at
117 seconds on CI's properly-configured lavapipe — roughly 70x slower here on a 9800X3D/RTX 4090
host. The two failures tagged `prerequisite skip outside the declared gate policy` require
matching a *named* adapter ("the Radeon iGPU"); `llvmpipe` can never satisfy that — not a flake,
structurally impossible every run under this configuration. Confirmed not the cause: no
`.wslconfig` cap, WSL2 sees all 16 logical processors and ~15 GB RAM with plenty free throughout;
ASan/UBSan's own ~2–3x overhead is normal.

### A4. Decision

Local WSL run stopped (confirmed no processes left running). Local WSL ASan remains fine for
narrow single-test debugging; a full merge gate now runs on cloud CI instead, which has neither
problem (plain Linux checkout — no autocrlf mismatch; `linux-clang-asan` doesn't run
GPU-adapter tests at all). Open follow-up, not done: promote one canonical, committed gate
script (the `core.autocrlf` override from `wsl_gate5.sh` + the lavapipe/`ANNO_REQUIRE_GPU` setup
from `gpu-tests.md`) out of gitignored `cache/`, so future local gates stop losing fixes already
made once.

## Part B — cloud CI was already broken (unrelated to this merge), then fixed

### B1. Discovery

Before trusting "push to cloud CI instead" as a real fix, checked CI's actual history:
**the last 30 consecutive runs on `main` are all failures**, back to at least 2026-11-03,
independent of anything in this session. The first push of `task/W4-main-1` (run `42004951625`)
inherited this: 7 of 9 jobs failed. None of the specific failures were caused by the CRLF fix
itself — all were pre-existing breakage in a pipeline nobody had been watching (local WSL/native
gates were the only validation actually in use).

### B2. The seven bugs found and fixed

Each was root-caused from the actual CI log text (not guessed), fixed, and — where practical —
verified locally before the next push.

**1. CMake `IN_LIST`/`CMP0057` error — blocked `linux-clang-asan` entirely (commit `82b4134b`)**
`src/app/AnnoAppSanitizerTimeouts.cmake:11` used `if("${name}" IN_LIST anno_app_tests_HEAVY_TESTS)`.
CTest's script-mode `if()` reader (used while including this file during test discovery via
`CTestTestfile.cmake`) doesn't set policy `CMP0057`, so `IN_LIST` is read as a literal unknown
argument, not an operator — a hard `CMake Error`, not a warning, failing every ASan build's test
inventory before any test ran. Fixed with `list(FIND ...)`, which has no such policy dependency.

**2. `clang-format` violation in `founding_fixture.hpp` — blocked `cpp-format` (commit `e223d72c`)**
Line 34 had a double space before a trailing `//` comment, introduced by the earlier CRLF fix in
this same session; clang-format 23.1.3 `--Werror` caught it. Single-space fix, verified against
the real pinned clang-format binary (locally installed via pip) across the whole `src/` tree, not
just the one file.

**3. macOS `-Werror` warnings — blocked `cpp (macos-clang)` build (commit `51c02d6f`)**
`src/test_support/tests/host_test.cpp` (5 call sites, lines 85/93/99/111/114): cast a `pid_t` to
`int` before passing it to `darwin_proc_info(std::uint64_t)` (`src/test_support/src/coord_wire.hpp:641`),
so Clang's `-Wsign-conversion` caught the implicit `int`→`uint64_t` conversion at the call,
redundant with (and inconsistent with) the existing pattern one line already used elsewhere
(`coord_wire.hpp:679`: `static_cast<std::uint64_t>(::getpid())`). Fixed by casting to
`std::uint64_t` directly at all five sites.
`src/test_support/tests/budget_f4_test.cpp:43`: `kPortClientLeak` is used only inside this file's
Linux-only `#else` branch (test F4/N4b); on macOS/Windows that branch compiles out, so Clang flags
the `constexpr` as unused. Marked `[[maybe_unused]]` with a one-line reason comment.

**4. Rust `wgpu` pipeline-layout mismatch — blocked `test (windows-latest)` (`cargo test`, commit `c78c3298`)**
`src/render/shaders/fluid.wgsl` declares `@group(0) @binding(5) var<uniform> SH: Ships`, used by
`eta_step`'s `ship_term()` — added for the C++ renderer's ship-wake feature, and the shader is
shared (`include_str!`'d) with the Rust reference. `crates/render/src/gpu_fluid.rs`'s bind
group/pipeline layout for `eta_step` only ever declared bindings 0–4, so wgpu's pipeline
validation rejected it outright (`Shader global ResourceBinding { group: 0, binding: 5 } is not
available in the pipeline layout`). The Rust reference has no ship model at all (confirmed:
zero "ship" references anywhere in `fluid.rs`/`gpu_fluid.rs` before this fix). Fixed by binding a
zeroed `Ships`-sized uniform buffer at binding 5 (`head.x`, the ship count, is 0, so
`ship_term` is a no-op) — behavior-preserving, no new feature, purely satisfies the shared
shader's binding contract. Verified locally with a real GPU adapter:
`cargo test -p anno-render --lib --features gpu -- gpu_fluid` (both `fluid_shader_is_valid_wgsl`
and `gpu_matches_cpu_reference` pass). Also ran `cargo fmt --all` (two spots needed rustfmt's
line-wrapping) and `cargo clippy --workspace --all-targets -- -D warnings` (clean) before pushing,
since the `lint` job runs both.

**5. Dead `run_selected_test.sh` — blocked every `cpp (linux-*)`/`windows-msvc` job's test step
(commits `82b4134b`, `5b6ee95a`)**
`tools/test/run_selected_test.sh`'s fixture never passed `--source-root`, so `run_selected.py`'s
`gate()` defaulted `source` to the real repo `ROOT`; the fixture's own `CMakeCache.txt` says its
home is the throwaway fixture dir, so `home != source` raised `"build directory belongs to a
different source tree"` → exit 5 (`FAIL: passing preflights: exit 5, expected 0`). Deeper: the
script drives the gate via `ANNO_RUN_SELECTED_PREFLIGHTS`/`_SOURCES`/`_PREFLIGHT_TARGETS` env
vars that **nothing in the current codebase reads anymore** (confirmed by grep: only the dead
test itself references them) — the real current mechanism is `--require-test <name>` plus two
fixed, hardcoded preflights (`cmake/CheckTestNames.cmake`, `ctest_verdict_test.py`) baked directly
into `run_selected.py`'s `preflight()`. `tools/test/workflow_test.py`
(`test_workflow_contract`, registered separately in `CMakeLists.txt`) already exercises this
exact contract through the *current* interface — comprehensively (21 test methods, including the
precise bad-test-name/semicolon case the old script tested via a separate fixture project) — and
was already passing in the same CI run. Rather than rewrite a parallel fixture around a dead
interface, retired the dead test: removed its `add_test(NAME run_selected_contract ...)` block
from `CMakeLists.txt` and deleted the script. Verified: `ctest --preset msvc -N` no longer lists
it; `cmake --preset msvc` reconfigures clean.

**6. A racy assertion in `picture recovery: a generation that outlives the bridge...`, found on
`linux-gcc` (commit `9df52d7e`)**
`src/app/tests/scene_picture_recovery_test.cpp:524`: `CHECK(SceneReclaimer::shared().stats().completed
== before)` failed with `1 == 0`. Root cause (traced through the actual ownership/deleter code,
not guessed): `render::Scene` uses a custom shared_ptr deleter
(`SceneReclaimDeleter`, `src/render/src/scene.cpp:430,734`) that hands a last-reference drop to
`SceneReclaimer`'s background worker rather than destroying inline.
`ScenePicture::commit()` (`src/app/src/scene_picture.cpp:863,954,962`) drops its own copy of the
*base* generation on its own internal reaper thread asynchronously, inside the test's inner
block; the test's own `scene` variable is the last remaining owner of that base generation, so
`scene.reset()` is what actually zeroes its refcount and queues it on `SceneReclaimer` — whose
single worker thread can then finish that queued job before the next line runs, with nothing
serializing the order. The test's real intended guarantees (the drop on this thread doesn't block
for an inline destroy; the eventual destruction runs on a different thread) don't depend on that
ordering and are already covered by the existing deadline-polled check a few lines later for
`completed >= before + 2` (both generations). Removed the racy mid-test `CHECK` with a comment
explaining why; left the non-racy final check intact. Verified locally (MSVC, Windows): the test
and its neighbors in the same file/suite all pass.

**7. `ctest_verdict.py`'s platform-skip classifier missed two real phrasings — blocked every
`cpp` job's test step after (1)–(6) were fixed (commit `b1e95579`)**
Once the build-blocking issues above were cleared, every `cpp` job (`macos-clang`,
`linux-clang-asan`, `linux-gcc`, `linux-gcc-release`, `windows-msvc`) still failed identically with
`VERDICT: FAIL prerequisite skip outside the declared gate policy`. `src/test_support/tests/budget_f3_test.cpp:330`
and `budget_f4_test.cpp:440` (tests F3/D2 and F4/N4) skip with "...the real PowerShell meter is
not available (it **runs only from WSL**...)"; `budget_f4_test.cpp`'s macOS branch (F4/N4b) skips
with "...reads /proc/\<pid\>/fd, **which only Linux has**". Both are exactly "a capability the
host lacks" — the `PLATFORM` category's own documented definition
(`tools/test/ctest_verdict.py:12`) — but neither phrasing matched the existing `PLATFORM` regex
(`WSL \(Ubuntu\) is not available|\bon Windows\b|POSIX shell`), so both fell through to the
catch-all `other` category, which is not allowed by default and fails the gate. Broadened the
regex to also match `runs only from WSL` and `which only Linux has`, and added both exact
phrasings as regression cases to `ctest_verdict_test.py`'s existing
`test_platform_skips_are_reported_not_executed_and_do_not_fail`. To make sure nothing else in the
codebase would hit the same gap, wrote a one-off script that imports `classify()` and scans every
`MESSAGE("skip...")` call site in `src/**/*.cpp` (handling C++ adjacent string-literal
concatenation); the only other `other`-classified messages found all require
`ANNO1503_GAME_DIR` set to a specific partial game directory or a specific scenario file, which
cloud CI never does (it runs with `--asset-policy unavailable`, i.e. the var unset) — confirmed
none of them appear in any of the four jobs' actual `SKIPPED(other)` output in this run, so they
were left alone as out of scope for this incident.
Verified: `python3 -I tools/test/ctest_verdict_test.py` → 24/24 pass. Also ran
`python3 -I tools/test/workflow_test.py` directly on this Windows host to double-check: it fails
13/21 **identically with or without this change** (confirmed via `git stash`), i.e. a pre-existing
Windows-native (non-WSL) incompatibility unrelated to this fix — and it already passes as
`test_workflow_contract` inside the real cloud CI run, which is what actually matters.
