### 2. Project goals and constraints

#### What it is

From `CLAUDE.md` and `docs/PLAN.md` §0:

- Same game, stable, with **robust deterministic multiplayer**, QoL, and modern performance.
- Targets: **Windows and Linux x86_64**. macOS is a development host only, never a release target.
- Original files required; never redistributed.
- **Faithful core vs improvements:** original rules live in `sim`; QoL and visual upgrades are opt-in (`Rules`, render styles). Enhanced water (breakers, flowing rivers, ships sitting in water) is an owner-preferred improvement, not the default faithful look.

#### Non-goals (explicit or implied)

- macOS as a ship target.
- Shipping original assets.
- Silent edits to original rules.
- Guessing constants into code (they go in `docs/open-questions.md`).
- New features in the Rust crates (frozen reference).
- Hardcoded engine limits (PLAN §0.1): original counts are data/config; `formats` may mirror file layouts.

#### Language / porting strategy

**ADR 0001** (`docs/adr/0001-cpp20.md`) supersedes ADR 0000 (Rust). New code is C++20 under `src/`. Rust `crates/` stays until C++ parity, then is removed. There is **no ADR 0002** yet (T34 is supposed to write one for the original’s float walk, emulated in integer).

Practical split today:

| Area | C++ (`src/`) | Rust (`crates/`) |
|---|---|---|
| formats, assets, render, app, anno-dump, bench_frame | **main line**, further than Rust on rivers/zoom/sim | frozen reference; rivers behind C++ |
| anno-extract | **not ported** | exists |
| sim | **only real implementation** | empty stub (`lib.rs` + `Cargo.toml`) |
| net, ui | **absent** | empty stubs |
| Python oracles | `tools/*.py` + `agree.py` | n/a |

#### Determinism rules (sim)

From CLAUDE.md and `docs/sim/state.md` §0.2, enforced mechanically by `tools/lint_sim.py` (registered as CTest when Python 3 is found; **required in CI** via `ANNO_REQUIRE_LINT`):

- Integer / fixed-point in checksummed state.
- Seeded PRNG owned by the sim (original MSVC `rand()` table, 2048 entries, seed 1).
- No wall clock, no `std::unordered_map`, no pointer-order iteration.
- No float in hashed state; `/fp:strict` / `-ffp-contract=off`.
- No exceptions in `formats`/`sim` (`Result<T,E>`).
- No global mutable state; no UB (ASan/UBSan in CI).
- Explicit little-endian field lists for hash/save/load — never struct dumps.

Load-time float conversion of `PROD3` (original x87 order) is allowlisted. Figure motion in the original uses floats (OQ-162 decided → T34, not implemented).

#### Design extras (owner)

- **§0.1** No hardcoded limits; sea sprite `ANLAGEN` 2801 and three zoom groups should become config.
- **§0.2** Improve, don’t only rebuild (enhanced water is the flagship).
- **§0.3** Measured 60 fps targets; GPU for pixels; CPU reference path.
- **§0.4** Decode, never redraw; pixel-exact assets.
- **§0.6** Up to **8 players**; world grows above 4 (OQ-100 decided). Generator not started (M4.1).

### 3. Architecture and repository layout

#### Intended dependency direction

```
formats  ←  assets  ←  render  ←  app (viewer)
formats  ←  sim  (headless; no SDL/GPU)
formats  ←  sim_load  (scenario file I/O wrapper)
net, ui  — planned, not present in src/
```

CMake root (`CMakeLists.txt` lines 1–2) states this. `anno_sim` links **only** `anno_formats` (`src/sim/CMakeLists.txt`). Scenario loading that needs the filesystem lives in `src/sim_load` so `sim` stays I/O-free. The viewer **does not consume sim**:

```cmake
# src/app/CMakeLists.txt (lines 1–12)
# anno1503: the application (for now the island viewer). anno_app_core holds
# the window-independent parts (scene loading, PNG output) so tests can use
# them; the window needs SDL3 (ANNO_BUILD_VIEWER).
add_library(anno_app_core
  src/cli.cpp
  src/loader.cpp
  src/png.cpp
  src/still.cpp
)
target_include_directories(anno_app_core PUBLIC include)
target_link_libraries(anno_app_core PUBLIC anno_render)
```

```cpp
    const E& error() const {
        assert(!ok());
        return std::get<1>(v_);
    }
```

In **NDEBUG / MSVC Release**, `assert` is compiled out. Then `std::get<0>` on an error `Result` throws `std::bad_variant_access` — an exception from the library that is forbidden to throw. Confirmed policy hole; not a known production crash if callers check `ok()` first.
