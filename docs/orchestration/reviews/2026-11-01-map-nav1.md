## Findings

### [P2] Check every traversed tile in route fixtures

`tools/ship_nav_ref.py:342` adds each run's displacement and checks its final
endpoint, without checking intermediate tiles or diagonal corner clearance.
In V7, the wall occupies x=30..31, z=0..39. Replacing the recorded detour
`SE10 SE9 S1 E3 NE10 NE8 N2` with `E10 E10 E10 E10` sails straight through
that wall to the same endpoint. Both `check_routes` and `route-selftest` still
pass. Thus an invalid path can become a green implementation oracle. Expand
runs tile by tile, enforce map bounds, enterability and both diagonal side
tiles, and make this precise corruption a negative control. Separately compare
the production router's actual runs with the expected runs; geometric legality
alone cannot establish original tie order or cost behavior.

### [P2] Make planning admission fair across repeated registry visits

`docs/sim/ship-navigation.md:138` resets a four-plan quota each Advance and
lets the first eligible ships in registry order consume it. Retrying later in
the same registry order does not guarantee service. With 100 registry slots,
five-tick Advances visit ten slots at a time. Put five continuously eligible
ships in slots 1..5; repeatedly replace orders on the first four. Each cycle
begins that batch at the same place. A model of the documented rule over 1,000
Advances admits the first four 100 times each and the fifth zero times.
Introduce deterministic, persisted fairness state or an equivalent bounded
service rule. Replacements must not continually move a pending ship ahead of
an older waiter. Test sustained competing requests, cancellation/removal and
save/load while waiting, not only a finite initial burst.

## Decisions for MAP-NAV-2

- **Approved:** distinguish atomic command refusal from a later failed route.
  A valid accepted order may later leave the ship idle and emit `RouteFailed`.
  Include a reason and command/order identity; quota deferral is not failure.
- **Approved in principle:** integer movement with a fine accumulator and
  retained fractional carry. The exact representation is conditional on the
  independent arithmetic checks in package D. Do not promote the unproven
  long-voyage drift bound into an established fact. State every rounding point,
  denominator and domain; persist all carry that affects later results.
- **Approved:** check ownership against the authoritative issuer, not an
  untrusted payload field. This is a simulation boundary requirement; a
  headless test is not proof that a future network transport authenticates peers.
- **Approved:** save authoritative motion, pending admission and carry with a
  new stream version; original-save import may deliberately initialize idle.
  Mirror carried scout/donkey positions through the existing effects protocol.
- **Approved for the first headless slice only:** defer local detours and hostile
  avoidance, explicitly allowing ship overlap. Peace does not remove friendly
  ship collisions in the original. This deferral is not full peaceful-navigation
  fidelity, combat readiness or late-game scalability acceptance.
- **Approved:** bounded, serial, deterministic planning as a correctness-first
  implementation. The first-come quota in the submitted contract is not approved.
  Use fair bounded admission and explicit `BudgetExceeded` reporting. Do not
  increase quotas merely to hide starvation or claim scalable performance from
  the five-ship canary.
- **Approved:** data-driven navigation facts/rules and explicit content identity.
  Preserve original defaults while validating alternate types and larger maps.
  Unsupported values must fail validation rather than overflow or truncate.

## Close these prerequisites without restarting the whole investigation

1. Pin the goal-selection callback/Offer behavior and object-height contribution
   to blocked tiles/coarse data before implementing those paths. The contract
   currently points to an unresolved density tie and an unread object predicate
   while promising an exact route port. These affect the chosen approach and
   passage through real islands. Reuse the existing narrow leads, including
   `cache/map2-nav1/RK-stamp-reset.md`, `0x100a48c0`, `0x1000f260`,
   `0x10090350` and the builder/update callers. Do not substitute a blanket
   building-footprint block or an arbitrary tie and label it original.
2. Reconcile the documents with the final evidence: the matrix still says route
   vectors are absent and block-edge behavior is untested; the RE comparison
   says a lake route is an atomic refusal whereas the contract defers failure.
   Distinguish outside-to-lake reachability from a voyage entirely within a lake.
3. Specify a real stop/cancel command or explicit command mode, its validation
   and codec identity; the first-slice promise includes stopping but only
   `MoveCmd` has a payload today. Never overload a valid `(0,0)` target silently.
4. Correct numeric claims: a nearest-Q32 conversion has an **absolute** error
   bound of at most 2^-33, not that relative bound for every small speed. Pin
   supported domains, exact carry and failure behavior before serialization.
5. Give remaining runtime unknowns explicit implementation boundaries. A land
   start's candidate behavior must be resolved or a conservative, named rule
   chosen before that branch is implemented. Do not wait on UI pick rounding
   to implement exact headless targets. Do not expand the Windows rendering
   executor's current assignment.
