# Simulation core: time, randomness, state hash

Spec for `src/sim` (`anno_sim`), the deterministic simulation (PLAN M3). Evidence: [`docs/re/tick-loop.md`](../re/tick-loop.md) (static analysis of the GOG 2.0.0.5 binaries; D = disassembled/decompiled, P = parsed from game files). Everything here is integer arithmetic; no float takes part in simulation state.

## World PRNG
- **Table:** `T[i]` = the `i`-th output (0-based) of the MSVC CRT `rand()` after `srand(1)`: `x ← x · 214013 + 2531011 (mod 2³²)`, output `(x >> 16) & 0x7fff`. Length 2048 in the original (D: `AnnoWelt.dll` `0x100a3980`). The original's table at `AnnoWelt.dll` `0x100cb8f8` equals this sequence entry for entry (P/D, 2026-10-17). Facts (tick-loop.md §3): SHA-256 of the 4096 bytes (u16 LE) `41bc794652bedbd69cd452d4b34a4877a92ccf1effea4c0b116d56706b45efdc`, min 21, max 32757, 1991 distinct values; our own check value: sum 33,419,328. `src/sim/tests/sim_test.cpp` compares the generated table with the DLL's bytes when the game files are present.
- **Draw:** `cursor ← (cursor + 1) mod len; return T[cursor]` (D: world slot `+0xb4` = `0x100a1740`). The cursor is the only state; the sequence repeats every `len` draws.
- **Seed:** the host's game seed (`rand() % 2048 + 1` at host start-up, sent in the lobby) is written through world property 8, which stores `value mod len` (u32 value, `divl` by the length; D: `AnnoFrame.dll` `0x1009b978`, `AnnoWelt.dll` `0x100a3230`, `0x100a32ac`). `World(seed)` does the same.
- **Fixture F6:** cursor 0 → 18467, 6334, 26500, 19169, 15724; cursor 2047 → 41, 18467, 6334; cursor 1000 → 1528, 26679, 7864.
- **Not simulation randomness:** the original also calls the CRT `rand()` (seeded with `GetTickCount`) for cosmetic variants and effect jitter (tick-loop.md §3). The rebuild gives those effects their own generator outside `sim`; they never touch the world PRNG or the state hash.
- Configuration: any non-empty table may be used (`WorldRng::from_table`, which refuses an empty one); the original's is the default.

## Time
- **World clock:** a 64-bit count of game milliseconds; `tick = ms >> 1` (one tick = 2 ms). At the end of each advance the new tick is copied to `+0x108` (`last_tick`): between advances it equals the tick, during an advance it still holds the tick from before it (D: `Advance` = `0x100ae040`, copy at `0x100ae126`/`0x100ae12d`; `WorldClock::begin` adds the step and returns the tick, `end` does the copy, `advance` is both; fields `+0x100/+0x104`, `+0x10c`, `+0x108`). The original keeps the ticks in 32 bits and takes the step as a signed 32-bit value; the rebuild uses 64-bit ticks and unsigned steps. Game seconds as reported by the original: `tick / 500 + offset` (world property 7, unsigned division).
- **What an advance runs** (original order, D: `0x100ae040`): all islands; the timed-event queue (due tick ≤ now); sub-systems `+0x114`, `+0x118`, `+0x69c8`; a 30,000 ms re-evaluation (`0x1009d2a0`); a 7.5-minute island event with two PRNG draws (`0x100ae140`). Only the clock is implemented so far.
- **Island sweeps:** an incremental sweep over an island's 8 × 8-tile chunks processes `min(chunks · Δtick / period + 1, chunks)` chunks per call (none if the island has no chunks), `Δtick` = 16-bit tick difference since its previous call (zero-extended); period 2000 ticks (4 s) for the per-tile item phases (`0x1008b5f0`), 15,000 ticks (30 s) for island slot `+0x194` (D: `0x1008b760`, cap at `0x1008b7b3` and `0x1008b82a`). The original computes in signed 32 bits; the rebuild in 64 bits. The same shape (`min(d · n / div + 1, n)` with `d` the 16-bit stamp difference) paces every round-robin list of the world (city ring, building lists, player table, object manager; the figure registry's variant has no `+1`): `visit_count`, `visit_count_clamped`, `run_slot_list`, `run_scheduled_lists` and `pop_due` in `scheduler.hpp` ([`state.md`](state.md) §5.1) are those building blocks, proven against a transcription of the original's instruction sequence on the range where its signed 32-bit product is exact.
- **Step size, single-player:** per frame of `dt` real ms (the main loop clamps `dt` to 1000), `game_ms = trunc(dt · speed + 0.5)`, nothing advances if `game_ms < 1`, at most 100; the original then advances in a loop of pieces of at most 100 ms, which with that cap runs once (D: `AnnoFrame.dll` `0x1005b110`, cap `0x1005b12b`, loop `0x1005b13c`–`0x1005b172`, x87). The speeds a player can set — 50, 100, 200, 400 % (keys F8/F5/F6/F7, likely) and 0 (pause) — become f32 values via `pct · 0.01f`; the exact products lie just below 0.5, 1, 2, 4 and round to exactly those values under round-to-nearest, the default mode, which is **assumed** (not traced; tick-loop.md §6). Under that assumption `game_ms = (dt · percent + 50) / 100` (integer division) is exact; the test checks it against the original's float chain for every `dt` from 0 to 1000 ms. Other speeds are not original (`nullopt`; a `rules` option may add them).
- **Step size, multiplayer:** a turn every 100 ms real time from the host, 10 steps per turn, one step per 10 ms local real time, each advancing `trunc(speed · 10)` = `percent / 10` game ms (5/10/20) (D: `0x1005fe10`, `0x100559c0`). These are the defaults of `Timing`. 400 % is refused by the key handler in multiplayer (`0x100071b0`, net client slot `+0xfc` = `0x100609c0` for `tNetClientNet`); pause stops the host's turns instead of sending speed 0, so no step runs (`multiplayer_step_ms(0)` = `nullopt`).
- The rebuild keeps these rules as the faithful mode. A fixed-tick mode that does not lose time on slow frames is a QoL option for later, behind `rules`.

## State hash
- **`World::core_hash()`** (version 1, unchanged) = FNV-1a 64 (offset basis `0xcbf29ce484222325`, prime `0x100000001b3`) over, in this order: `clock.ms` (u64), `clock.last_tick` (u64), PRNG table length (u64), PRNG table digest (u64: FNV-1a 64 of the table as u16 LE), PRNG cursor (u32); all little-endian. It is kept so the old golden stays checkable.
- **`World::state_hash()`** (stream version `kStateHashVersion`, a development counter from 100 until the stream is frozen; [`state.md`](state.md) §9) is hierarchical: one field list per persistent type (`state_fields.hpp`) is run by a `HashArchive`; the digest of a scope is the FNV-1a 64 of its own primitives, and every child scope contributes its 64-bit digest (u64 LE) at the position where it appears. Names and ordinals of scopes are for addressing (`HashTree`) and are not hashed. Stage S3 (stream version 101) has three scopes: `header` (u32 `kStateHashVersion`, u32 `kPrngTimelineVersion`, then the `SimConfig`, the `Rules`, the u64 digest of the type registry and the seam names), `clock_rng` (the five v1 fields, so its digest equals `core_hash()`) and `settings` (the `WorldSettings`); the exact layout is `state.md` §9.3 and is pinned byte by byte in `src/sim/tests/config_test.cpp`. Every later state field is added to its type's field list with a version bump; the hash is never computed over memory images.
- **The PRNG table is shared and immutable** (`std::shared_ptr<const RngTable>`): copying a `WorldRng` or a `World` copies a pointer and the cursor, and a moved-from generator keeps its table. `WorldRng::stream(seed, slot)` (cursor from `rng_mix`, a splitmix64 finaliser) is defined for the optional per-island mode of [`state.md`](state.md) §4.2 and unused until then.
