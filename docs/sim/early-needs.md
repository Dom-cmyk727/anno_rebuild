## 7. Cloth contract (N1; reference and vectors committed before engine code)
Independent reference `tools/early_needs_ref.py` (CTest `early_needs_reference_agrees`, `early_needs_reference_contract`: bounded child runs, empty / malformed / missing file / wrong expectation / unknown key are refused, an echo stand-in fails), vectors `fixtures/synthetic/sim/early_needs_vectors.txt` (66, hand-derived first), C++ test `early_needs_vectors_test.cpp` (35 records run against the existing kernels: all agree; 31 `route`, `credit`, `trip`, `offer`, `farmrun`, `wrun` records are pending for N2). Evidence for each rule (AnnoWelt.dll `f220a878510f7407...`, local disassembly `cache/map2-research4/veto/AnnoWelt.dll.full.asm`):
1. **Farm tick `0x1006ea90`** (D, read instruction by instruction for this packet; class of PRODTYPE 2, 4, 6, 8, 10 = sheep farm 807): gate `(u16)(t - [+0xa]) >= 0x1f4` then `+= 0x1f4` (a word); `[+0x22] == 0` returns after the stamp; activity `[+0x1e]` `a*255>>8`; flag bits 4/5 return; `max_figures(0) == 1` with a taken slot skips production but still tests the dispatch; production: out `[+0x18]` against capacity `type+0xc0` (u16 compare, `jbe`) -> status 2 with no step; `q = (raw[+0x1c] << 7) / need` (signed idiv) capped at 128, below 64 -> status 1; `raw -= q*need >> 7`, `made = q*rate >> 7`, `out += made` (a word, so the check is before the step and the store may exceed the capacity), activity `+= made << 4`; dispatch (reached when max_figures > 1, or made is 0): attached slots `[+0x24..+0x34)` non-null count `<` max_figures, `384 / rate >= raw / need` (signed idiv), then one world draw (discarded), then `this+0x118(route, figure type, t)` with `route` = the figure type's ROUTETYPE (`slot +0x54`, `0x1006ee27`), and the new figure's cargo goods := input goods 0 (`type+0xb0(0)`, `0x1006ee4d`). A null result (`0x1006ee33`) attaches nothing and sets no cargo: the draw and the attempt still happened.
2. **Attach / detach** (D, Farm vtable `0x100c8ae0`): slot `+0x28` = `0x10074540`: a figure of class `0x1500` takes the first free of the five pointer slots, all full returns -1 (no counter exists, unlike the small farm's raised byte); slot `+0x2c` = `0x1006f070` clears the matching slot. So "attached figures" is the number of live non-null slots; the engine's `workers_out` counter is the same quantity (ADAPT: configured `max_figures` may exceed 5; the original has 5 slots).
3. **The job** (D, `0x1003b0e0`, `docs/re/forestry.md` 2.4, `small-farm-supply.md` 2.3): route 46 (`WEIDETIER`, table AnnoGame `0x10024fb8`) = job `0x2e` runs the animal case `0x1003b314` (step-A callback limit 20); 42 (`MAEHER`) = `0x2a`, 41 = `0x29` the worker case (limit 0); 45 (`FISCHER`) = `0x2d` shares the animal case. **Candidates are tiles of the home's square whose object type has `WARE[0]` = the figure's cargo goods and bit 29 clear; no owner or territory test exists** (so cutting grass in a neighbour's territory is allowed, no veto will be invented). Sheep: cargo goods GRAS (69), grass objects 2, 21, 23, 25, 27, 69, 71, 73, 79, 81, 83, 355.
4. **Cut and trip** (D, `0x10087340`, `0x10054530`, `0x1005c260`): the tile `id -> id - 1` when the predecessor is `ROHSTWACHS`, +256 cargo; the job repeats step A while `capacity > amount` (768 -> 3 cuts of 3 tiles, or fewer when no tile is left); step C hands the cargo to the home.
5. **Credit at the Farm** (D, Farm vtable slot `+0xc0` = `0x1006ee70`): `[+0x1c] += amount` as a word, no goods test, one raw store (the SmallFarm's slot choice `0x1006f960` is a different function).
6. **Weaver** (D, `docs/re/production.md` 4.1 and `transport.md`; the engine's Workshop kernel agrees with all 8 `wstep` vectors): `ratio = min(128, in*128/need)`, below 64 nothing, `made = rate*ratio >> 7`, `in -= need*ratio >> 7`; a carrier (job 0x33, capacity 768) is sent while `carriers_out < max_figures(0)` and the workshop has inputs. The carrier takes goods only from a source that holds **1 t (256)** of the goods; the input priority is 128 below 30 steps of stock+reserved+carried, 96 below 60, else none; score `priority + avail*192/capacity`.
7. **Units and thresholds that decide the chain** (hand-derived): one trip credits 768 raw grass (3 t); the sheep farm turns 768 into **52 wool in 9 steps** (8 x 87 -> 6 each, then 72 raw -> 4), leaving 1 raw; a weaver needs wool stock >= 1 t at the farm (256 = 43 steps) before a carrier takes any; 52 wool make 28 cloth in 5 steps. The chain is therefore a long-period process: expect hundreds of thousands of ticks for the first cloth.
8. **Renewal vs consumption:** the grass tile cut is consumed (`id - 1`), and regrows after the growth period of the grass object (102,000 ticks per `small-farm-supply.md` 2.4; cotton/sheep farms are not renewing by themselves beyond that). The canary must say whether the tiles it uses renew inside its run.
9. **Adaptations (named):** raw/out stores are u32 (original u16 words that wrap); `workers_out` replaces the pointer slots; the walker is the tile-level walker of forestry (`forestry.md` 3.8). **Not read:** the farm's growth-stage visual call `[+0x11c]` (display only); with `max_figures == 1` and a starved step the original tests an uninitialised stack word (`0x1006ed7f`) - the engine reads made = 0; no shipped sheep or pasture farm has `max_figures == 1`.
10. **Unsupported, refused (no silent fallback):** a Farm figure whose route is `0x2d` (fisher) or any route outside {0x29, 0x2a, 0x2e}: stays as today (no harvest state), documented; an animal job on a home that is not a Farm / SmallFarm payload is refused by the invariants.
11. **Engine gap to close in N2:** `consume()` gives a Farm figure the harvest state only for jobs 0x29/0x2a; job 0x2e on a Farm payload must get it (data-defined: the figure type's route, not a building id). Pasture and cattle farms with route 46 (820, 3011..) change with it (identity, section 9).
